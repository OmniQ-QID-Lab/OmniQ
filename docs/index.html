OmniQ · Residual Agents (RA)

Reimagining computational quantum research with AI scientists

Yuxuan Du, Hanqing Zhao, Xinbiao Wang, Yiming Lu, Kaining Zhang, Dacheng Tao

Nanyang Technological University, Singapore

Can AI scientists drive the next wave of discovery in computational quantum science? OmniQ turns published studies into executable reproduction tasks. Residual Agents (RA), an open-source AI scientist, learns from verified failures to improve future reproductions.

Abstract

AI scientists are expanding automated research across scientific domains, yet their ability to turn the scientific record into a foundation for autonomous discovery remains elusive. Here we uncover a fundamental barrier to this transition and demonstrate a route to overcome it in computational quantum science, where advances shape both what we can learn from complex quantum systems and what quantum computing can ultimately deliver. To identify this barrier, we introduce OmniQ, an expert-audited virtual research environment that converts published studies into executable reproduction tasks. Across 59 papers spanning classical simulation, quantum algorithms and quantum-property characterization, we systematically evaluate five agentic systems powered by large language models and six third-party agent harnesses. Our findings reveal that current AI scientists often fail to reproduce published results, exposing a fundamental mismatch between what scientific papers communicate and what autonomous agents require. By contrast, human expert intervention can turn these failures into successful reproductions, showing that the missing information can be identified and converted into reusable research experience. Guided by this observation, we develop Residual Agents (RA), a quantum-tailored self-improving AI scientist that distils externally verified workflow repairs into such experience. RA substantially improves research performance under fixed base models and limited adaptation budgets. For example, RA raises DeepSeek V4.1 Flash performance from 68% to 85%, matching Claude Code with Opus 5 at a third of its cost despite using a weaker base model. We integrate all reproduced results into an extensible platform built on the model context protocol, making verified research workflows directly accessible to AI scientists and allowing new scientific papers to be continuously incorporated. These results establish a new paradigm for computational quantum research, where published results become reusable scientific capabilities that support autonomous discovery.

Key results

Scientific record

Published studies have gaps

An auditing agent screened 3,376 judging outcomes from many agent runs, and domain experts confirmed reproducibility issues in 18 of the 60 curated studies. In 16 of them the missing detail could be recovered from released code or expert reading (Level I). One needed expert inspection to resolve a localized error (Level II), and one could not be resolved and was removed (Level III).

Frontier AI scientists

Performance varies widely

On the 59 tasks, Claude Code with Opus 5.5 reproduces approximately 93%, and Codex with several frontier models exceeds 70%; Codex with GPT-6-luna reaches only about 42%. Spending more does not guarantee success: several systems that use larger inference budgets than Opus 5.5 do worse, a “thinking more but doing less” behaviour. DSH with DeepSeek V4.1 Flash reaches approximately 68% at the lowest cost.

Agent harnesses

Harnesses tuned elsewhere do not transfer

With DeepSeek V4 Pro as the base model, six third-party harnesses reproduce 11 to 28 of the 59 tasks, and none beats DeepSeek’s own harness (29). Failure analysis shows agents that declare success without validating the result against the paper, replace the required computation with a cheaper surrogate, or silently reduce the problem size.

Residual Agents

RA learns from verified failures

RA raises DeepSeek V4.1 Flash from 68% to approximately 85%, at an inference cost of US$5.6 per task. That matches Claude Code with Opus 5 and Codex with GPT-5.6-sol API, which reach approximately 85% at US$16 and US$35 per task. RA is given 24 hours per task.

Three levels of reproduction issues

Experts graded every confirmed issue by its severity and by whether the scientific record can resolve it.

  1. Level I16 papers

    DefinitionMissing methodological details that can be recovered from the released code or expert interpretation.

    Example: #46Learning-based quantum error mitigation (Liao et al., Nat. Mach. Intell. 2024). The paper states that one feature is considered for the best split; the released code uses all features (max_features=1.0). Following the code recovers the reported extrapolation advantage.

  2. Level II1 paper

    DefinitionLocalized errors in the paper that can be resolved from the code, figures or broader scientific context, but otherwise lead to reproduction discrepancies.

    Example: #42Learning topological order without phase labels (Che et al., Nat. Commun. 2026). The silhouette coefficient drops from about 0.59 in the paper to 0.29 in the reproduction at circuit depth four. Recovering the reported value requires a two-step procedure that the paper does not describe.

  3. Level III1 paper

    DefinitionFundamental inconsistencies among the context, figures and released code that cannot be resolved through expert inspection.

    Example: #60Exponential concentration of quantum kernels (Thanasilp et al., Nat. Commun. 2024). The figure described as the kernel variance plots the variance of the distance C; at n = 2 it reaches 0.49, above the bound of 0.25 for a kernel with values in [0, 1]. The paper was removed from the benchmark.

Method

OmniQ: from a published paper to a judged reproduction

Given a full paper and a target result, an AI scientist must reconstruct the underlying method, implement and run it, and reproduce the reported outcome. Each task has two Markdown documents. The task specification guides the agent: it names the target figure and gives general guidelines and paper-specific instructions, without any expected values. The evaluation criteria are reserved for the judge: the structure of the figure, quantitative checkpoints with reference values and tolerances, and the required parameters and procedures. In the released runs these files are CLAUDE.md and JUDGE.md.

The judge, Claude Code with Opus 4.8, receives the criteria only after the run and inspects the code, logs, data and report. Every quantitative checkpoint is mandatory, and documenting an approximation does not excuse missing one. Each issue it finds is critical or non-critical. Figures pass only when no critical issue is found, and a task succeeds only when all its target figures pass.

Tasks were built and audited in seven steps that combine expert selection, LLM drafting, runs by many agent configurations, an audit of disputed verdicts and expert review.

RA: planner, executors and a critic

The planner splits a task into sub-plans linked in a dependency graph and assigns each requirement to exactly one sub-plan, with a resource budget and completion criteria for each. Every executor works in its own session. Before full-scale runs it validates its code on the smallest exactly solvable instance and times a representative step at the largest required size; long computations run as background jobs that the orchestrator tracks.

The critic sees the paper, the task specification and the execution records, but never the evaluation criteria. It checks where every number comes from, whether the method matches the paper and whether the sub-plan is complete. It then passes the sub-plan, returns it for local repair, or calls for a new approach. Results with fabricated or untraceable numbers are not eligible for ordinary repair.

For a new approach, three probe agents each test a possible cause of the failure with a small numerical experiment. Three critic sessions discard proposals that break fixed requirements, substitute prescribed methods or rely only on better agreement with the published figure without independent validation. They rank the rest by majority vote, and a fresh executor implements the winner. When a shared interpretation changes, the sub-plans that used it are reopened and reviewed again.

Experience: why “residual”

RA identifies the residual between failed executions and their verified corrections. Outside the reproduction runs, after each round of development experiments, an experience distiller turns these residuals into three memories: planner memory, critic memory and a residual memory of failure signatures. Each residual entry holds a description of the failure, a diagnostic check and a remedy. Lessons specific to one paper are excluded, and a human expert approves every update before it is used. During a run, the critic retrieves the matching residual entries and hands them to the executor that repairs the failed step.

The residual memory holds ten entries built from the five development tasks. The memory files ship with the code.

Benchmark

Five first-party agent systems were evaluated with models from the GPT, Claude, DeepSeek, Kimi and Grok families: Codex, Claude Code, Kimi Code, Grok Build and DeepSeek Harness (DSH). Six third-party harnesses ran on DeepSeek V4 Pro: mini-swe-agent and live-swe-agent (general software), InternAgent and DeepCode (scientific reproduction), and the Huxley–Gödel Machine (HGM) and Meta-Harness (evolved harnesses). Each task counts as reproduced only when it meets the strict criterion.

Reproduction success does not increase monotonically with inference cost, and existing harnesses can even degrade performance. RA lies on the Pareto frontier between DSH with DeepSeek V4.1 Flash and Claude Code with Opus 5.5. RA is given 24 hours per task, and the size of its marker shows its longer wall-clock time.

Trajectories

All 59 RA runs behind the paper’s evaluation will be released on Hugging Face under CC BY 4.0, with each task’s specification, evaluation criteria and judge verdict. Each run holds RA’s plans, the critic’s reviews and repairs, the code and outputs of every sub-plan, the orchestrator’s event ledger and logs, the final message of every agent session, the final report and the reproduced figure. Of the 59 runs, 50 pass the strict judge.

Inside these runs, the critic rejects more than half of intermediate results, triggering repair or replanning. Of the successful tasks, 90% need at least one correction, including all 13 tasks that RA reproduces beyond DSH.

The dataset leaves out the source papers and every copy of their text, pages or figures; third-party packages, code and data that the agents downloaded, which are listed with source and licence; and large arrays, binary data and text files over 2 MB, each listed with its size and SHA-256. Runs therefore cannot be re-judged exactly from the dataset alone.

Each task folder has a short guide, an index with one line per agent session and a list of every original file. The loader ra_traj.py needs only the Python standard library and reads loose and zipped files alike. Because the dataset contains the benchmark’s evaluation criteria, please keep it out of training corpora.

Featured runs

DSH and most DeepSeek V4 Pro harnesses failed these three tasks; RA passed all three. None of the three papers had an issue in the curation audit.

Sub-plan decomposition

Paper #2: fix the target, then split the work

Tindall et al., PRX Quantum 5, 010308 (2024): tensor-network simulation of IBM’s 127-qubit kicked Ising experiment · arXiv:2306.14887

Strict judge: pass

DSH compared the tensor-network estimate of a weight-23 observable with the exact value of the weight-17 observable, so its errors came out far larger than the published ones. RA identified the correct target observable before execution and split the task into five independently validated sub-plans, with the exact benchmark built independently of the simulation engine. When the full-scale run exposed an error in the belief-propagation code, RA corrected the affected sub-plans and kept the validated benchmark. The final errors agree with the published values to within about 2% at 15 of the 23 evaluated points.

Critic-guided local repair

Paper #35: the critic catches a broken bound

Giurgica-Tiron et al., Quantum 6, 745 (2022): low-depth algorithms for quantum amplitude estimation · arXiv:2012.03348

Strict judge: pass

DSH found the noisy crossover at εC ≈ 0.05γ, well below the expected scale, and still declared success; the judge failed it because the crossover fell outside the evaluation interval [0.3γ, 3γ]. RA’s first attempt also underestimated the cost, and its executor blamed the published curve. The critic instead checked the recorded circuit depths against the method’s bound, found that the circuit-selection rule violated it, and returned the sub-plan for local repair. After the fix, the crossover moved into the evaluation interval at all three noise strengths, and the judge passed both target figures.

Experiment-driven diagnosis

Paper #29: test the diagnosis before the repair

Rudolph et al., Nat. Commun. 14, 8367 (2023): tensor-network pretraining of parameterized quantum circuits · arXiv:2208.13673

Strict judge: pass

DSH and RA both failed at first. The KL divergence stayed above 1 after 50 training sweeps against a target range of 0.015 to 0.03, and the transfer fidelities were 0.9641 (DSH) and 0.9777 (RA) against a required 0.990. Guided by entries from its residual memory, the critic sent three probe agents per sub-plan to test its hypotheses in small experiments. Two found errors in the tensor contractions of the gradient; one found that the circuit conversion did not follow the paper’s truncation-and-disentangling procedure. After a majority vote, RA corrected both sub-plans and reproduced the reported performance curves.

The paper’s figure for this case includes a panel from the source article, so it is not shown here.

Code

RA is open source under the MIT licence. The repository holds the RA code used in the paper’s evaluation: the orchestrator, the planner, critic and residual memories, an offline test suite, and the tools to run RA on an OmniQ task and judge the result. In the paper, RA runs DeepSeek V4.1 Flash through DSH and is given 24 hours per task.

residual_agents/
The orchestrator, the ra command and the memory files.
tests/
Offline unit and end-to-end tests; no network and no API key.
infra/
Model proxy with token accounting, container recipe, task runner, batch-scheduler templates, judge runner and cost settlement.
examples/
Small synthetic task, a guide to running an OmniQ task, and a script that summarizes a published run.
fragments/, tools/
Orchestrator source, build script and integrity data (prompt and memory hashes).
docs/
Architecture, configuration, running, judging, known issues, trajectories and a glossary of the names in the code and runs.

Quick start

# Install and check: no API key and no network needed (Linux)
git clone https://github.com/OmniQ-QID-Lab/OmniQ
cd OmniQ
python3 -m pip install -e .
ra verify                  # build, prompt fingerprints, memory hashes
bash tests/run_all.sh      # offline unit and end-to-end tests

# Run one task in a container, through the local model proxy
docker build -f infra/container/Dockerfile --target runner -t residual-agents:1.0.0 .
infra/run/run_task.sh --task <task folder> --paper <your copy of the paper> \
    --paper-num N --label demo --out runs --ncpus 16 --mem-gb 128 --profile paper \
    --upstream <OpenAI-compatible endpoint, e.g. https://openrouter.ai/api/v1> \
    --key-file <file that holds your API key>

# Judge the finished run with the task's criteria (needs the Claude Code CLI)
infra/judge/judge.sh --run runs/paper_N/demo_pN --judge-md <JUDGE.md of the task> \
    --paper <your copy of the paper> --paper-num N --out verdicts \
    --key-file <file that holds your Anthropic API key>

RUNNING.md covers Apptainer, batch schedulers and a small synthetic task to try first; JUDGING.md describes the judge. Task specifications and criteria come from the trajectory dataset. The source papers are not redistributed, so bring your own copy of each paper, and keep the criteria file out of the task folder: the launcher refuses a folder that contains it.

Requirements. Linux with Docker or Apptainer; an OpenAI-compatible endpoint that serves DeepSeek V4.1 Flash with image input; DSH 0.1.5-rc.1 on Node 23.8 or later, installed in the image; the CPU cores and memory listed for each task; up to 24 hours per task.

Safety. Agents run with full shell permissions inside the container, so run RA only in a container. The proxy keeps the API key out of the agents’ sandbox; without the proxy, agents can read the key.

Reproducing the paper. Exact re-runs are not possible: DeepSeek has since updated V4.1 Flash in place, and verdicts depend on the judge model. RUNNING.md and JUDGING.md explain the settings.
